# Каталог Ґуґлі: як працює база і як додати бренд

## Дозвіл на фото
- Зараз (листопад 2026): факультет домовився з бізнесами, що на етапі студентського проєкту фото товарів брендів
  можна показувати. Письмових дозволів від кожного бренду ще немає.
- Далі, перед будь-яким публічним запуском чи рекламою, пишемо кожному бренду окремо (шаблон нижче) і зберігаємо
  відповідь. Бренд, який відмовив, ховаємо: `import_brand_db.py` без нього + товари `in_stock = false`.
- Ми не продаємо: показуємо фото, назву й ціну і ведемо на сторінку товару на сайті бренду (переходи рахуємо в `clicks`).

## Конвеєр (5 кроків)

```
brands.json ──► scrape.mjs (+ scraper.js) ──► guglya_<brand>.json ──► merge.py ──► products.json
                                                                                    │
brand_popularity.json ─────────────────────────────────────────────► import_brand_db.py ──► Postgres (RDS)
                                                                                    │
                                                         embed.py (FashionCLIP-вектори фото)
                                                                                    │
                                                         classify_gender.py (unisex → жін./чол.)
```

1. **`data/database/brands.json`** — список брендів. Поля: `id` (латиницею, без пробілів), `name`, `site`,
   `instagram`, `brand_type`, `audience` (`Жінкам` / `Чоловікам` / `Ж + Ч`), `segment` (Бюджет / Масмаркет /
   Середній / Преміум), `default_gender` (`female` / `male` / `null`), `kind` (`clothes` / `shoes`).
2. **Збір** (Андрій): `cd data/database && npm install && node scrape.mjs --out <папка> --only <id>`.
   Справжній Chrome через Playwright відкриває сайт і запускає `scraper.js`: спершу Shopify `/products.json`,
   далі sitemap + JSON-LD, далі обхід меню. До 300 товарів на бренд. Результат: `<папка>/guglya_<id>.json`.
3. **Російські назви → українські** (якщо сайт віддає російську навіть на українській версії, як Stimma й Solmar):
   `python3 data/database/ua_names.py <папка>/guglya_<id>.json [--lang-prefix /ua]` — бере назву з <title>
   української сторінки товару. Імпорт у будь-якому разі пропускає російські назви.
4. **Злиття**: `python3 data/database/merge.py <папка> --keep` → `products.json` (уся база), `<id>/products.json`,
   `categories.json`. `--keep` лишає бренди, яких немає в папці (сирі файли Андрія не потрібні). Тут
   нормалізуються кольори, тип речі (Пальто, Кеди…), слот, стать.
5. **Популярність**: `data/database/brand_popularity.json` — `{ "<id>": { "instagram": "...", "instagram_followers": N } }`.
   Заповнюємо вручну з Instagram (автоматичний збір Instagram заборонений їхніми правилами).
6. **Імпорт у базу сайту** (з кореня репо, `export AWS_PROFILE=guglya`):
   ```
   export DATABASE_URL=$(aws ssm get-parameter --name /guglya/database_url --with-decryption \
     --query Parameter.Value --output text --region eu-central-1)
   backend/.venv/bin/python backend/ml/import_brand_db.py      # бренди + товари
   backend/.venv/bin/python backend/ml/embed.py                # вектори фото для нових товарів (кілька хв)
   backend/.venv/bin/python backend/ml/classify_gender.py      # unisex → жіноче/чоловіче за фото
   ```
   Повторний запуск безпечний: бренди оновлюються за назвою, товари за посиланням (`product_url`). Товари, яких
   більше немає у файлі, стають `in_stock = false` (не видаляються: на них можуть посилатися образи й кліки).
   Сховані адміном товари (`is_hidden`) лишаються схованими. База пускає лише IP з `var.my_ip_cidr`
   (terraform.tfvars); з нової мережі спершу оновіть його.

## Що імпорт пропускає
- аксесуари (слот `other`: сумки, прикраси, ремені, шарфи), товари без фото, «немає в наявності»;
- **товари без ціни в гривнях** — зараз не на сайті Anna October, Ksenia Schnaider, Knitlab (ціни не знайдені),
  Ali Saulidi, WHY ME, Blast Out Studio (лише $); O.Taje — усе «немає в наявності»;
- **російські назви** (ы/э/ъ/ё, «мужской», «в цвете»…);
- ціни нижче 100 ₴ (помилка збору, напр. «8 990» → 8).

## Стать
- зі сторінки товару (жіноче/чоловіче), інакше `default_gender` бренду, інакше `classify_gender.py` за фото;
- `"keep_unisex": true` у brands.json (German Apparel, Cuprum Depot, O(FourFour)) — завжди унісекс;
- чоловічим образам пропонуємо лише чоловіче, жіночим — жіноче + унісекс.

## Сумки й шарфи
- `kind` у brands.json: `bags` / `scarves` (як `hats`): scraper.js не обмежує їм аксесуари 30-ма.
- **Сумки — слот `bag`** (міграція 009, як у data/database/README.md): імпорт бере `slot: "bag"`, а сумки старих
  зборів (`other` + «Сумка») розпізнає за назвою й ставить вид: Сумка / Кросбоді / Шопер / Клатч / Рюкзак;
  гаманці, чохли, ремені — не сумки. Альтернативи — лише того ж виду. Конструктор образів теж додає сумку.
- **Шарфи слота не мають**: бренди шарфів (Famo, My Scarf, DOLYA, Bobkova, OLIZ) лежать у data/database, на сайті
  приховані — вирішимо разом (у Famo й Bobkova переважно одяг).
- `--only id1,id2` в import_brand_db.py і classify_gender.py: імпорт/стать лише цих брендів (не чіпає чужі —
  коли хтось паралельно імпортує свої).

## Як працює підбір
- **Слоти**: hat, outer (пальто, куртки), jacket (піджак), top (светр, сорочка, футболка), dress (сукня,
  комплект, костюм — замість верху+низу), bottom, shoes.
- **Схожість**: FashionCLIP (512-вимірні вектори фото), косинусна відстань у pgvector.
- **Альтернативи** до речі в образі: той самий слот, інші бренди (спершу по одній на бренд), стать образу
  (чоловічим — лише чоловіче, жіночим — жіноче + унісекс), схожість ≥ 0.6, бонуси: той самий тип речі
  (+0.06), популярність бренду (+0.05 × (70% Instagram + 30% наших кліків)).
- **Конструктор образів** (/admin): Claude Sonnet 4.6 (Bedrock) описує речі на фото → FashionCLIP перетворює
  опис у вектор → пошук по каталогу.

## Чек-лист нового бренду
1. Український бренд, продає онлайн з цінами в гривнях, є одяг/взуття (не лише аксесуари).
2. Рядок у `brands.json` (+ `default_gender`, якщо бренд лише жіночий/чоловічий — це сильно покращує фільтр статі).
3. Підписники в `brand_popularity.json`.
4. Збір → merge → імпорт → embed → classify_gender (кроки 2–5).
5. Перевірка: кількість товарів бренду в базі, кілька фото відкриваються на guglya.studio (деякі бренди блокують
   показ фото на чужих сайтах), стать і кольори виглядають правильно.
